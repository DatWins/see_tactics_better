**Stack:** Hugo (hugo-scroll theme) + vanilla JS flashcards + Lichess puzzle CSV

---

## What the site does

Flashcard training site for chess tactics. Each card shows:
- A chessboard at a position **8 moves before the puzzle** (game context)
- The 8 lead-in moves listed as text
- A "White/Black to move" badge
- A prompt ("Find the fork.", "Mate in 2.", etc.)

Flipping the card shows the solution move sequence plus a Lichess link.

**Board orientation:** automatically flipped — Black to move shows Black at bottom.

## How to add a new puzzle theme section

### Step 1 — Add theme to `filter_puzzles.py`

In `THEME_MAP`, add:
```python
"my-theme-slug": "lichessThemeTag",
```
In `PROMPT_MAP`, add:
```python
"my-theme-slug": "Find the best move.",
```

Lichess theme tag names: https://lichess.org/training  
(e.g. `fork`, `pin`, `skewer`, `mateIn2`, `kingsideAttack`, `discoveredAttack`, `sacrifice`, …)

### Step 2 — Generate the JSON (run on Windows in repo root)

**Without game context (fast):**
```powershell
python filter_puzzles.py --csv lichess_db_puzzle.csv --theme my-theme-slug
```

**With 8-move game context (slow — ~200 Lichess API calls, ~2 min):**
```powershell
python filter_puzzles.py --csv lichess_db_puzzle.csv --theme my-theme-slug --context
```

Output: `static/data/my-theme-slug.json`

### Step 3 — Create a Hugo content page

Create `content/en/homepage/NN-my-theme.md` (NN = weight number for menu order):
```markdown
---
title: "My Theme Title"
header_menu_title: "My Theme Title"
navigation_menu_title: "My Theme Title"
weight: 3
header_menu: true
---
{{< submenu "My Theme Title|my-theme-slug" >}}

## My Theme Title
{{< flashcard-deck category="my-theme-slug" title="My Theme Title" >}}
```

### Step 4 — Commit and push

```powershell
git add static/data/my-theme-slug.json content/en/homepage/NN-my-theme.md filter_puzzles.py
git commit -m "Add my-theme-slug puzzle section"
git push
```

## Puzzle CSV format (Lichess)

Download from https://database.lichess.org/#puzzles  
File: `lichess_db_puzzle.csv.zst` → decompress with `zstd -d`

Columns (no header row):
```
PuzzleId, FEN, Moves, Rating, RatingDeviation, Popularity, NbPlays, Themes, GameUrl, OpeningTags
```

**Key detail:** `FEN` is the position *before* `Moves[0]`. `Moves[0]` is the opponent's forced lead-in. The puzzle solver starts at the position *after* `Moves[0]`. So:
- `startFen` = FEN column (shown on front card, 8 moves back if context available)
- `puzzle.fen` = board after `Moves[0]` only — **captured right after pushing the first move in the loop**
- `puzzle.solution` = `Moves[1:]`

### Critical bug that was fixed (2026-11-22)

`uci_to_san(board, uci)` pushes each move onto `board` in place. The old code called `board.fen()` after the entire loop, so `puzzle.fen` was the position after ALL moves (lead-in + full solution), giving the wrong side-to-move. Fixed by capturing `puzzle_fen = board.fen()` inside the loop at `i == 0`.

## flashcard.js — key facts

**Board rendering** (`buildBoard` / `renderPieces`):
- SVG-based, cburnett pieces embedded as `<defs>`
- Takes a `flipped` boolean: when `true`, renders with Black at bottom (reverses rank labels 1→8, file labels h→a, mirrors piece positions)
- `flipped = (puzzleColor === "Black")` — set automatically based on `puzzle.fen`

**Data fields read from JSON:**
| Field | Used for |
|---|---|
| `contextFen` | Starting board position (8 moves back) |
| `contextMoves` | Lead-in move list shown as text |
| `startFen` | Fallback if no contextFen |
| `moves` | Fallback lead-in moves |
| `puzzle.fen` | Determines who is to move (badge + board flip) |
| `puzzle.solution` | Solution moves shown on back |
| `puzzle.prompt` | Text prompt shown on front |
| `site` | Lichess training link on back |

**Turn badge:** reads `puzzle.fen` (field 2 = `w`/`b`) → "White to move" / "Black to move"

**Theme tags** are hidden via CSS in `custom_head.html`:
```css
[id$="-theme"] { display: none; }
```

## Lichess Game Context API

`filter_puzzles.py --context` fetches game context from:
```
GET https://lichess.org/game/export/{game_id}?moves=true&tags=false&clocks=false&evals=false&opening=false&literate=false
Accept: application/x-chess-pgn
```

**Must use `Accept: application/x-chess-pgn`** — JSON is not available for this endpoint.

The PGN is parsed by stripping tag lines, move numbers, and comments with regex, then replaying with `board.push_san()`. Position matching uses only the first 4 FEN fields (ignores clocks).

`time.sleep(0.5)` between calls to be polite to Lichess.
